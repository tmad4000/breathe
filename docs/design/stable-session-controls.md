# Breathe: one stable mode menu

**Decision: use one compact top-bar mode menu in idle, running and paused states, showing only the current mode and a chevron. Remove the mode pills. Keep the two guided behaviors, rename Coach → Adaptive breathing and Guide → Fixed breathing. Show only the current pattern in one compact chip, in the same position in every state. Tapping opens the choices.**

Author: Astra dd5f9ff5, for Jacob / root d3caa262. Implementation owner: Sol cfd4bfbf. 2026-11-15. This is a design decision and handoff, not product code or a deployment.

Jacob’s follow-up is included: “the pattern tap-to-switch doesn't need to show all the possible patterns you can switch between right there either.” This supersedes the inline pattern options and the earlier state-dependent mode layout in NEXT-STEPS §6.

## Why this decision

Mode is an occasional change of activity; the breathing experience and Start/Pause/Resume should dominate. Moving navigation when Start or Pause is pressed makes the app feel like two interfaces. A stable current-value menu is the clearest solution here. The general principles’ preference for segmented choices does not override Jacob’s explicit request for compact pattern choices or this task’s authorization to decide one stable mode pattern.

Coach and Guide are behaviorally distinct enough to keep: Adaptive breathing starts near the measured pace and gradually lengthens toward the selected target; Fixed breathing plays the selected timing immediately and never requests camera access. Merging them would conceal an important difference in timing and camera use. Their current names fail to communicate it. Adaptive without tracking continues on its existing schedule; it must say “Camera off · following a schedule,” never imply live adaptation. Turning tracking off does not silently turn an adaptive session into a fixed one.

The menu has the same five choices in every state:

| Visible name | Existing stored value | Explanation in the opened menu |
|---|---|---|
| Adaptive breathing | coach | Gradually slow toward a pattern; camera tracking optional |
| Fixed breathing | guide | Follow a fixed pattern; no camera |
| Respiration Tracker | respiration | Measure your breathing with the camera |
| Coherence · fingertip | finger | Measure with a finger over the camera |
| Coherence · hands-free | remote | Measure with the front camera |

Keep internal IDs, stored preferences, old deep links and historical records compatible. No algorithm change is implied. Remove the separate Coherence camera selector: its two methods already have unique entries in this same menu. Do not collapse them into one “Coherence” entry only in some states.

## Implemented change list

1. **One mode control.** In `index.html`, retain/rework `#modeSelect` as the sole top-bar current-name control; remove `#modeTabs` and `#coherenceChoiceLabel`. In `app.js`, remove tab generation and state syncing for removed controls. In `styles.css`, remove the idle/paused hiding of `.topbar .title` and running hiding of tabs. Reserve the same header geometry in every state; hide version on phones and put it in Settings → About, preserving honest update time. Keep debug and Sound hit targets accessible; camera flip belongs with the camera viewport so the longest mode name fits. On desktop use the same menu, not a second tab presentation.
2. **Rename the behaviors consistently.** Update option labels, introductory copy, fallback buttons (“Use Fixed breathing”), live switch announcements, Settings sections, History display names, help and accessible names to the table above. Preserve IDs `coach`, `guide`, URLs `?coach`/`?guide`, persistence and export schema. Resolve legacy history labels through a display-name map; do not rewrite saved session data. A native select is acceptable if accompanying menu help cannot fit; a custom menu must implement focus/keyboard behavior fully.
3. **Exactly one pattern entry point on the canvas.** Remove `#patternChips` and “Pattern · tap to switch.” Reuse `#quickPattern` as an always-visible current-value control for both guided modes, idle/running/paused, just above the transport. Label it “Pattern · 5–1–5–1 ▾”; accessible name expands units: “Breathing pattern: 5 seconds in, hold 1, 5 out, hold 1.” Other closed values: “Pattern · 5–5 ▾” and “Pattern · 4–7–8 ▾.” The opened list spells out in/hold/out and seconds. Show only the selected value while closed. Replace the large repeated idle timing with brief explanatory copy. During adaptation this chip identifies the target; the live timing may be shown separately as noninteractive progress (“Now … → target …”), never another pattern selector.
4. **Pace uses the same current-value pattern.** Non-guided modes show one “Pace · Off ▾” or “Pace · 6/min ▾” in that location throughout the session. All existing options remain. This is guide pace, not a measured reading: accessible name “Guide pace”; panel label “Guide pace.” Preserve the distinct measured breaths/min display.
5. **Replace the Tune tray with stable controls.** Remove `#respTuneBtn`, `.resp-tray-open` state and automatic folding of `#quickControls`. The current pace chip stays above the transport in Respiration Tracker at every state. Keep the camera filling the stage, chart-focus toggle, pan fixes, safe areas and overlay fade. No expansion should move the camera or breathing chart. Menus overlay and dismiss; they do not reflow the experience.
6. **One Sound panel.** Top speaker opens a short Sound panel at every state. It contains “All sound: On/Muted,” “Guide tone: On/Off,” and “Detected breath tone: On/Off,” with the latter explained as a tick for measured inhale/exhale. Remove the two canvas tone chips. Settings has a “Sound…” link to this same panel, not duplicate checkboxes. `M` can continue to mute globally. Preserve each tone preference under mute; show “All sound is muted” inside the panel instead of relying on color or hover titles. Guide tone is unavailable with guide pace Off; detected tone is unavailable in Fixed breathing or with tracking off, with a short reason. Preserve the visual guide while tones are off. Use consistent labelled state controls and expose their state to assistive technology.
7. **Remove Settings duplication and misleading labels.** Settings → “Session controls…” opens/focuses the same pattern/pace control; do not retain a separate editable “Coach pattern” or a second “Breathing guide” pace. Put shared display choices under “Breathing view”; show camera/tracking options only where relevant. Keep History, advanced camera/display controls, recording settings and About in the gear sheet. This is consolidation, not removal of functionality. Settings tone text must distinguish master sound, guide tone, detected tone and optional video recording.
8. **Keep debug small and truthful.** Preserve the 6px dot, 11px “debug” idle / “rec” while actually recording and ≥40px target opening Debug details. Keep the persistent off switch, local-only explanation and retention behavior. In paused state show rec only if recording is actually continuing; otherwise “debug · paused.” Do not repurpose this as the camera or sound state. First-run explanation once, no card. Both the indicator and Settings must open the same debug section. Do not restore the large 0.12.0 Debug ON treatment.
9. **Keep lossless switching and explicit pending values.** Mode switch saves exactly as Stop, starts a new linked session with shared `groupId`; running remains running, paused switches to ready-to-Start. No discard question, no mode Undo. Preserve camera across transitions that require it; release it entering Fixed breathing. Switching camera method may reconfigure acquisition. Choosing the already selected mode is a no-op (especially Coherence hands-free). If acquisition fails, keep saved data and show the destination’s fallback. Pattern/pace stay in the current session, apply at the next inhale/breath boundary, log the marker, announce the pending change and offer Undo for five seconds. Paused changes take effect at the next resumed breath. The chip may show the new target immediately but the live phase must not claim it has already changed. Undo cancels a pending change or schedules restoration at a safe boundary; never snap the live guide midway through a breath.
10. **Acceptance matrix.** At 390×844 and 1280×800, for all five modes: idle → Start → Pause → Resume; running mode switch and paused mode switch; current pattern/pace list open/close/change/Undo; master mute with each tone preference; camera denial/loss/recovery; Coherence method switch. Assert exactly one visible mode selector, no inline pattern list, no duplicate Coherence selector, same mode vocabulary and stable positions. Confirm one dominant transport action: Start, then Pause, then Resume; Stop remains secondary. Verify saved group links, no lost records, no camera request for Fixed breathing, unchanged guide timing when toggling audio, persistence and old deep links. Check keyboard reachability, current selection announcement, Escape/outside dismissal and focus return for every custom menu/panel; adequate contrast and ≥40px targets. Verify on actual iPhone separately before claiming iOS parity.
